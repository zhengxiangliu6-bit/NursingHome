========================================
  养老院管理系统 - 第一阶段开发总结
  "数字孪生基础" (Digital Twin Foundation)
========================================


一、技术架构
────────────────────────────────────────
后端: Django 4.2 + Django REST Framework + SQLite (开发) / PostgreSQL (生产)
前端: Vue 3 + Element Plus + Pinia + Axios + ECharts
认证: JWT (simplejwt)，6种角色 (超级管理员、管理员、医生、护士、护工、家属)
基础模型: BaseModel (UUID主键、软删除 is_deleted、created_at、updated_at)


二、已有基础模块 (第一阶段之前)
────────────────────────────────────────
- 用户认证与角色管理 (accounts)
- 老人基本信息管理 (residents)
- 房间与床位管理 (residents)
- 护理等级定义 (residents)
- 护理评估记录 (residents)

三、第一阶段新增功能
────────────────────────────────────────

1. 床位状态扩展
   - 原状态: available(空闲)、occupied(已占用)
   - 新增状态: leave(请假)、reserved(预留)、maintenance(维护中)、cleaning(清洁中)
   - 共6种状态，覆盖床位全生命周期

2. 床位状态图 (BedMap)
   - 页面: frontend/src/views/residents/BedMap.vue
   - API: GET /api/v1/beds/map/
   - 按 楼栋 -> 楼层 -> 房间 -> 床位 层级展示所有床位实时状态
   - 不同状态以不同颜色标签区分，直观掌握全院床位分布

3. 入住退住流程 (AdmissionProcess)
   - 页面: frontend/src/views/residents/AdmissionProcess.vue
   - 模型: AdmissionApplication (咨询 -> 评估 -> 签约 -> 已完成 四阶段状态机)
   - API: /api/v1/admission-applications/
   - 支持操作: 推进(advance)、拒绝(reject)、撤销(withdraw)、办理入住(admit)、办理退住(discharge)
   - 签约阶段可预留床位，办理入住时填写身份证号并分配床位/护理等级/责任护士
   - 已完成阶段可办理退住，退住后释放床位(进入清洁中状态)
   - 支持删除已完成/已拒绝/已撤销的记录
   - 操作按钮使用 flex-wrap 布局，自适应排列

4. 老人请假流程 (ResidentLeave)
   - 模型: ResidentLeave (on_leave/returned/cancelled)
   - API: POST /residents/{id}/start_leave/、POST /residents/{id}/end_leave/、GET /residents/{id}/leaves/
   - 在老人详情页一键请假/销假
   - 请假期间床位标记为"请假"状态，保留床位不释放
   - 销假后床位自动恢复为"已占用"
   - 请假记录在老人详情页独立 Tab 展示

5. 床位调换申请 (BedTransfer)
   - 页面: frontend/src/views/residents/BedTransfer.vue
   - 模型: BedTransfer (pending/approved/rejected/cancelled)
   - API: /api/v1/bed-transfers/
   - 支持两种场景:
     * 调换: 老人换到空闲床位
     * 互换: 两个老人交换床位
   - 申请 -> 审批 -> 自动执行的完整工作流
   - 互换使用 transaction.atomic 原子操作，临时置 NULL 绕过 OneToOne 唯一约束
   - 支持操作: 通过(approve)、拒绝(reject，可填原因)、取消(cancel)、删除(delete)
   - 状态筛选: 全部/待审批/已通过/已拒绝/已取消

6. 员工排班管理 (StaffSchedule)
   - 页面: frontend/src/views/accounts/StaffSchedule.vue
   - 模型: StaffSchedule
   - API: GET /api/v1/auth/schedules/ (支持 date_from/date_to 范围参数)
   - 支持早班/午班/夜班排班

7. 员工管理增强 (StaffManage)
   - 页面: frontend/src/views/accounts/StaffManage.vue
   - 员工列表与管理

8. 老人详情增强 (ResidentDetail)
   - 新增照片上传功能
   - 护理等级、床位选择
   - 家属联系人 Tab (添加/移除家属关联)
   - 请假记录 Tab (展示请假历史)
   - 退住流程 (退住后记录最后床位号 last_bed_info)
   - 保存/退住后自动返回老人列表页面

9. 房间管理增强 (RoomManage)
   - 支持编辑/删除房间
   - 房间内床位管理 (增删)


四、关键技术实现
────────────────────────────────────────

1. 软删除
   - 所有删除操作均为 is_deleted = True，查询时自动过滤 filter(is_deleted=False)
   - 避免数据丢失，支持数据恢复

2. 床位状态联动
   - 入住时: 床位 -> occupied
   - 退住时: 床位 -> cleaning，记录 last_bed_info
   - 请假时: 床位 -> leave (保留关系)
   - 销假时: 床位 -> occupied (恢复)
   - 调换时: 原子操作交换/移动床位

3. __str__ on None 防护
   - 所有 CharField(source='xxx.__str__') 改为 SerializerMethodField
   - 关联对象为空时返回 None 而非报错或显示乱码
   - 涉及: bed_info、reserved_bed_info

4. last_bed_info 字段
   - Resident 模型新增 last_bed_info CharField
   - 退住时保存最后床位号 (如 "201-1")
   - 老人列表中退住老人仍可显示其历史床位

5. 路由注意事项
   - residents/rooms、residents/bed-map、residents/admission、residents/bed-transfer
     必须放在 residents/:id 之前，避免路由冲突
